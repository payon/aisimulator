## 2. 위험 상세 및 대응

### R-01: 외부 AI API 서비스 장애 🔴 Critical

**설명**: OpenAI, Gemini, Grok, Claude API 서비스가 일시적 또는 영구적으로 장애 발생

**영향**:
- AI 채팅/퀴즈 기능 완전 불가
- 이미지 변환/미래 모습 기능 불가
- 사용자 경험 심각 저하

**대응 전략**:
1. **폴백 메커니즘**: 모든 외부 API 실패 시 z-ai-web-dev-sdk(내장 AI)로 자동 전환
2. **에러 핸들링**: 사용자 친화적 에러 메시지 + 재시도 안내
3. **다중 제공자**: 하나의 제공자 장애 시 다른 제공자로 전환 가능
4. **Graceful Degradation**: 부분적 기능 장애 시에도 UI는 정상 동작

**잔여 위험**: 내장 AI도 장애 시 서비스 완전 중단 (확률 Very Low)

---

### R-02: API 키 유출 🟠 High

**설명**: AI 제공자 API 키가 의도치 않게 외부에 노출

**영향**: API 키 도용, 과도한 과금 청구, 계정 정지

**대응 전략**:
1. **서버 사이드 호출**: API 키는 브라우저가 아닌 서버에서만 사용
2. **UI 마스킹**: 입력 필드 type="password", 미리보기 8자리만
3. **응답 필터링**: 설정 API 응답에서 전체 키 미반환
4. **환경 변수**: .env 파일을 통한 키 관리 지원

**잔여 위험**: DB에 평문 저장 (로컬 환경에서는 허용, 프로덕션에서는 암호화 필요)

---

### R-03: 프롬프트 인젝션 공격 🟡 Medium

**설명**: 사용자가 악의적 입력으로 시스템 프롬프트를 우회하거나 AI 동작을 조작

**영향**: AI가 의도치 않은 콘텐츠 생성, 시스템 프롬프트 노출

**대응 전략**:
1. **패턴 기반 탐지**: 10개 이상의 인젝션 패턴 감지
2. **시스템 프롬프트 보호**: 사용자 입력으로 시스템 프롬프트 변경 불가
3. **고정 응답**: 시스템 프롬프트 질문 시 고정 답변
4. **입력 길이 제한**: 최대 2,000자

**잔여 위험**: 새로운 인젝션 기법 탐지 불가 (지속적 패턴 업데이트 필요)

---

### R-04: 인메모리 세션 손실 🟡 Medium

**설명**: 서버 재시작, 메모리 부족 등으로 인메모리 세션이 초기화

**영향**: 모든 관리자가 강제 로그아웃, 작업 중단

**대응 전략**:
1. **자동 복구**: 클라이언트 checkAuth() → 로그인 폼 자동 표시
2. **사용자 안내**: "세션이 만료되었습니다. 다시 로그인해주세요." 메시지
3. **localStorage 유지**: 토큰은 클라이언트에 저장 (재시작 후 세션 검증 시 401)

**잔여 위험**: 서버 재시작 빈도가 높으면 사용자 경험 저하

**완화 방안**: 향후 Redis 세션 스토어 도입

---

### R-05: SQLite 동시성 제한 🟢 Low

**설명**: SQLite의 단일 쓰기 제한으로 동시 사용자 환경에서 병목

**영향**: 동시 쓰기 시 데이터베이스 잠금, 응답 지연

**대응 전략**:
1. **WAL 모드**: SQLite Write-Ahead Logging 활성화
2. **읽기 최적화**: 대부분의 작업이 읽기
3. **Prisma 재시도**: 내장 재시도 로직

**잔여 위험**: 대규모 환경에서는 PostgreSQL 마이그레이션 필요

---

### R-06: 무차별 대입 공격 (Brute Force) 🟠 High

**설명**: 공격자가 관리자 로그인 엔드포인트에 무차별 비밀번호 대입

**영향**: 계정 탈취, 시스템 전체 장악

**대응 전략**:
1. **bcrypt 지연**: 해시 검증 자체의 계산 지연 (~100ms)
2. **Rate Limiting**: AI API에 적용된 제한 (관리자 API는 별도 제한 미적용)
3. **강력한 기본 비밀번호**: admin123 (초기 로그인 후 변경 권장)

**잔여 위험**: 관리자 API에 별도 Rate Limit 미적용

**완화 방안**: 향후 로그인 실패 횟수 제한 (5회 실패 시 15분 잠금)

---

### R-07: 세션 탈취 (Session Hijacking) 🟡 Medium

**설명**: 공격자가 관리자의 세션 토큰을 탈취하여 인증된 상태로 접근

**영향**: 관리자 권한으로 시스템 조작, 데이터 변조

**대응 전략**:
1. **HTTPS**: 모든 통신 암호화
2. **UUID 토큰**: 122비트 엔트로피로 추측 불가
3. **24h TTL**: 세션 자동 만료
4. **즉시 무효화**: 로그아웃 시 서버에서 즉시 삭제

**잔여 위험**: localStorage XSS를 통한 토큰 탈취 가능

**완화 방안**: 향후 HttpOnly 쿠키 + CSP 헤더

---

### R-08: 관리자 계정 잠금 🟡 Medium

**설명**: 유일한 superadmin이 비밀번호를 잊거나 계정이 비활성화됨

**영향**: 시스템 관리 불가, 콘텐츠·설정 변경 불가

**대응 전략**:
1. **기본 계정**: admin@aiplatform.kr/admin123 항상 존재
2. **superadmin 보호**: 마지막 superadmin 삭제/비활성화 방지
3. **DB 직접 접근**: 최악의 경우 DB에서 직접 계정 복구 가능

**잔여 위험**: 기본 비밀번호 변경 후 잊어버린 경우

**완화 방안**: 비밀번호 재설정 스크립트 또는 DB 직접 업데이트

---

### R-09: 감사 로그 유실 🟢 Low

**설명**: 감사 로그 작성 실패 또는 DB 오류로 로그가 누락

**영향**: 추적성 저하, 보안 사고 조사 불가

**대응 전략**:
1. **비차단 로깅**: logAction 실패 시 주 작업은 계속 진행
2. **콘솔 에러**: 실패 시 콘솔에 에러 출력
3. **try-catch**: 감사 로그가 예외를 전파하지 않음

**잔여 위험**: DB 오류 시 로그 유실

---

### R-10: XSS 공격 🟡 Medium

**설명**: 악의적 스크립트가 관리자 대시보드에 주입되어 실행

**영향**: 세션 토큰 탈취, 관리자 권한 도용

**대응 전략**:
1. **React 이스케이핑**: JSX 기본 HTML 이스케이핑
2. **HTML 새니타이징**: sanitizeHTML() 함수
3. **입력 검증**: 콘텐츠 값에 스크립트 태그 차단

**잔여 위험**: DOM 기반 XSS 가능성

**완화 방안**: 향후 CSP 헤더 추가

---

### R-11: 권한 에스컬레이션 🟡 Medium

**설명**: 낮은 권한의 사용자가 높은 권한의 작업을 수행

**영향**: 권한 없는 콘텐츠 수정, 사용자 관리, 설정 변경

**대응 전략**:
1. **RBAC**: 모든 API 라우트에서 권한 검사
2. **서버 사이드 검증**: 클라이언트 검증만 의존하지 않음
3. **superadmin 보호**: 마지막 superadmin 강등 방지

**잔여 위험**: 권한 검사 누락 가능성 (코드 리뷰로 완화)

---

### R-12: AI 생성 콘텐츠 부정확 🟠 High

**설명**: AI가 부정확하거나 편향된 정보를 생성 (할루시네이션)

**영향**: 잘못된 정보로 사용자 오인, 신뢰도 저하

**대응 전략**:
1. **시스템 프롬프트 제한**: 의료/법률/금융 조언 금지
2. **간결한 응답**: 3문장 이내 제한
3. **면책 안내**: AI 응답은 참고용임을 명시

**잔여 위험**: AI 할루시네이션 완전 차단 불가

---

### R-13: 서버 메모리 부족 🟠 High

**설명**: 인메모리 세션, 이미지 처리 등으로 서버 메모리 부족

**영향**: 서버 크래시, 서비스 중단

**대응 전략**:
1. **NODE_OPTIONS**: --max-old-space-size=2048
2. **Rate Limiting**: 동시 요청 수 제한
3. **세션 정리**: 만료 세션 자동 정리
4. **이미지 크기 제한**: 10MB 업로드 제한

**잔여 위험**: 다수 동시 이미지 처리 시 메모리 압박

---

### R-14: CMS 콘텐츠 오염 🟡 Medium

**설명**: 잘못된 콘텐츠 값(빈 값, 무효 JSON 등)이 프론트엔드에 반영

**영향**: UI 깨짐, 기능 오동작, 사용자 혼란

**대응 전략**:
1. **fallback 값**: useCmsContent(key, fallback)로 기본값 보장
2. **JSON 검증**: type=json 콘텐츠 저장 전 유효성 검사
3. **30초 캐시**: 오염 전파 지연 (즉시 수정 가능)
4. **감사 로그**: 변경 전후 값 기록으로 롤백 가능

**잔여 위험**: fallback 미설정 키는 빈 값 표시

---

### R-15: Service Worker 캐시 오염 🟡 Medium

**설명**: 공격자가 중간자(MITM) 공격 또는 XSS로 Service Worker 캐시를 오염

**영향**: 악의적 콘텐츠 제공, 피싱, 데이터 탈취

**대응 전략**:
1. **immutable 헤더**: 정적 자산에 `Cache-Control: immutable` 설정하여 캐시 변경 방지
2. **SW 업데이트 검사**: SW 활성화 시 `update()` 호출로 최신 버전 확인
3. **HTTPS 강제**: PWA는 HTTPS에서만 동작하여 MITM 공격 차단
4. **캐시 버전 관리**: 캐시 이름에 버전 포함으로 오염 캐시 자동 무효화

**잔여 위험**: SW 설치 전 최초 접속 시 MITM 가능 (HTTPS로 완화)

---

### R-16: 푸시 알림 남용 🟡 Medium

**설명**: 공격자가 푸시 알림 구독을 악용하여 스팸 또는 피싱 알림 전송

**영향**: 사용자 스팸 피해, 피싱 링크 클릭, 알림 권한 신뢰도 저하

**대응 전략**:
1. **구독 검증**: `/api/pwa/subscribe`에서 구독 객체 유효성 서버 검증
2. **Rate Limiting**: `/api/pwa/notify`에 전송 빈도 제한 (분당 최대 N회)
3. **VAPID 인증**: 서버 VAPID 비공개 키로 알림 발신자 인증
4. **사용자 제어**: PWASettingsPanel에서 알림 수동 해제 가능

**잔여 위험**: VAPID 비공개 키 유출 시 위조 가능

**완화 방안**: VAPID 키 순환(롤테이션) 체계 구축

---

### R-17: 오프라인 데이터 노후 🟢 Low

**설명**: 사용자가 오프라인 상태에서 오래된 캐시 데이터를 열람

**영향**: 노후 정보로 잘못된 판단, UI 불일치

**대응 전략**:
1. **stale-while-revalidate**: 캐시 데이터 즉시 제공 + 백그라운드 갱신
2. **Background Sync**: 온라인 복구 시 자동 데이터 동기화
3. **OfflineIndicator**: 오프라인 상태 시각적 표시로 사용자 인지
4. **캐시 TTL**: API 응답 캐시에 적절한 만료 시간 설정

**잔여 위험**: 장기 오프라인 시 데이터 불일치 가능

---

### R-18: TWA 서명 키 유출 🟡 Medium

**설명**: TWA Android 앱 서명 키(keystore)가 유출

**영향**: 위조 앱 배포, assetlinks.json 기만, 사용자 피싱

**대응 전략**:
1. **키 교체**: 유출 즉시 새 키 쌍 생성 및 재서명
2. **assetlinks.json 갱신**: 새 SHA256 지문으로 Digital Asset Links 업데이트
3. **키 저장소 분리**: keystore 파일 버전 관리 제외, 안전한 저장소 사용
4. **Google Play 서명**: Play Console의 앱 서명 기능 활용

**잔여 위험**: 키 교체 전 유출 창구 시간 동안 위조 가능

**완화 방안**: 키 교체 자동화 파이프라인 구축

---

### R-19: 하이드레이션 불일치 🟢 Low

**설명**: SSR/CSR 간 렌더링 결과 불일치로 React 하이드레이션 경고 발생

**영향**: 콘솔 경고, UI 깜빡임, Radix UI aria-controls ID 불일치

**대응 전략**:
1. **useClientValue 패턴**: `useSyncExternalStore` 기반으로 SSR/CSR 값 분기
2. **useHydrated 훅**: 클라이언트 하이드레이션 완료 후에만 클라이언트 전용 값 사용
3. **서버 스냅샷**: SSR 시 고정값 반환, CSR 시 실제값 반환
4. **Radix UI 호환**: aria-controls 등 동적 ID 속성에 useClientValue 적용

**잔여 위험**: useClientValue 미적용 컴포넌트에서 여전히 불일치 가능
