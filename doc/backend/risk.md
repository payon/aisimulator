# Risk Assessment (리스크 평가)

> 본 문서는 시니어 사용자 디지털 복지 서비스 플랫폼의 리스크 평가 결과를 설명합니다.
> 기술적 리스크, 보안 리스크, UX 리스크, 운영 리스크 및 각 완화 전략을 포함합니다.

---

## 1. Technical Risks (기술적 리스크)

### 1.1 DB Migration 실패

| 항목 | 내용 |
|------|------|
| **리스크 설명** | Prisma schema 변경 시 데이터베이스 마이그레이션이 실패하여 서비스 중단 발생 |
| **확률** | 중간 (3/5) — 개발 단계에서 스키마 변경 빈번 |
| **영향도** | 높음 (4/5) — 서비스 전면 중단, 데이터 손실 가능 |
| **위험도** | 🔴 12/25 (High) |

**완화 전략 (Mitigation):**
- 마이그레이션 전 SQLite 데이터베이스 백업 수행
- `prisma migrate diff`로 변경사항 사전 검토
- `db:push` 대신 `migrate deploy` 사용 (프로덕션)
- 롤백 스크립트 사전 준비
- 스테이징 환경에서 마이그레이션 선 검증

### 1.2 AI API 장애

| 항목 | 내용 |
|------|------|
| **리스크 설명** | AI 제공업체 API 장애, 응답 지연, 또는 할당량 초과로 챗봇 서비스 불가 |
| **확률** | 중간 (3/5) — 외부 API 의존성 |
| **영향도** | 중간 (3/5) — 챗봇 기능만 영향, 핵심 서비스는 유지 |
| **위험도** | 🟡 9/25 (Medium) |

**완화 전략 (Mitigation):**
- AI API 호출 타임아웃 설정 (10초)
- 폴백 응답: "현재 AI 서비스가 일시적으로 불가능합니다. 잠시 후 다시 시도해주세요."
- 응답 캐싱: 유사 질문에 대한 이전 응답 재활용
- 다중 AI 제공업체 지원 (Primary/Secondary)
- 장애 시 시니어 사용자에게 대체 경로 안내 (전화번호, 방문 안내)

### 1.3 세션 스토어 메모리 부족

| 항목 | 내용 |
|------|------|
| **리스크 설명** | In-memory 세션 스토어가 메모리 누수 또는 대량 세션으로 인한 메모리 부족 |
| **확률** | 낮음 (2/5) — 세션 수 제한 존재 |
| **영향도** | 높음 (4/5) — 서버 크래시, 전체 서비스 중단 |
| **위험도** | 🟡 8/25 (Medium) |

**완화 전략 (Mitigation):**
- 사용자당 최대 3개 세션 제한
- 만료 세션 1시간마다 자동 정리
- 세션 스토어 크기 모니터링 (임계값 10,000개)
- 임계값 초과 시 가장 오래된 세션 자동 삭제 (LRU)
- 메모리 사용량 모니터링 및 알림
- 장기적: Redis 외부 세션 스토어 마이그레이션 고려

### 1.4 WebSocket 연결 불안정

| 항목 | 내용 |
|------|------|
| **리스크 설명** | 네트워크 불안정으로 WebSocket 연결 빈단절, 실시간 기능 장애 |
| **확률** | 중간 (3/5) — 공공 Wi-Fi, 키오스크 네트워크 환경 |
| **영향도** | 낮음 (2/5) — 실시간 업데이트만 영향 |
| **위험도** | 🟢 6/25 (Low) |

**완화 전략 (Mitigation):**
- 자동 재연결 (최대 5회, 지수 백오프: 1s, 2s, 4s, 8s, 16s)
- 연결 끊김 시 폴링 폴백 (30초 간격)
- 사용자에게 연결 상태 시각적 표시
- 키오스크 환경에서 유선 네트워크 권장

## 2. Security Risks (보안 리스크)

### 2.1 토큰 탈취

| 항목 | 내용 |
|------|------|
| **리스크 설명** | Bearer 토큰이 XSS, 네트워크 스니핑, 또는 기기 접근으로 탈취 |
| **확률** | 낮음 (2/5) — HTTPS + XSS 방어 적용 |
| **영향도** | 매우 높음 (5/5) — 계정 완전 탈취 |
| **위험도** | 🟡 10/25 (Medium-High) |

**완화 전략 (Mitigation):**
- HTTPS 강제 (모든 환경)
- 짧은 세션 TTL (24시간)
- IP 주소 변경 시 세션 무효화 (선택적)
- 동시 세션 수 제한 (3개)
- 관리자 세션은 더 짧은 TTL 적용 (4시간)
- 세션 무효화 API 제공 (관리자)

### 2.2 무차별 대입 공격 (Brute Force)

| 항목 | 내용 |
|------|------|
| **리스크 설명** | 자동화된 로그인 시도로 계정 탈취 |
| **확률** | 높음 (4/5) — 자동화 공격 흔함 |
| **영향도** | 높음 (4/5) — 계정 탈취, 권한 남용 |
| **위험도** | 🔴 16/25 (High) |

**완화 전략 (Mitigation):**
- Rate Limiting: 로그인 5회/15분
- 계정 잠금: 5회 실패 시 30분 잠금
- 점진적 지연: 실패 시 응답 시간 증가 (1s → 2s → 4s...)
- CAPTCHA: 3회 실패 후 CAPTCHA 요구
- 실패 로깅 및 관리자 알림
- IP 기반 차단 (10회 이상 실패한 IP)

### 2.3 XSS 공격

| 항목 | 내용 |
|------|------|
| **리스크 설명** | 사용자 입력을 통한 Cross-Site Scripting 공격 |
| **확률** | 낮음 (2/5) — React 기본 이스케이프 + CSP |
| **영향도** | 높음 (4/5) — 세션 탈취, 데이터 유출 |
| **위험도** | 🟡 8/25 (Medium) |

**완화 전략 (Mitigation):**
- React JSX 자동 이스케이프 활용
- Content Security Policy (CSP) 헤더 설정
- dangerouslySetInnerHTML 사용 금지 (ESLint 규칙)
- 입력 정화 (sanitize-html)
- 정기 보안 감사 ( 의존성 취약점 스캔)

### 2.4 프롬프트 인젝션

| 항목 | 내용 |
|------|------|
| **리스크 설명** | AI 챗봇 입력을 통한 시스템 프롬프트 조작 시도 |
| **확률** | 중간 (3/5) — AI 서비스 확대에 따른 공격 증가 |
| **영향도** | 중간 (3/5) — 비인가 정보 노출, 잘못된 응답 |
| **위험도** | 🟡 9/25 (Medium) |

**완화 전략 (Mitigation):**
- 패턴 매칭 기반 인젝션 탐지 (7개 이상 패턴)
- 사용자 입력과 시스템 프롬프트 명확 분리
- AI 응답 후처리 (민감 정보 필터링)
- 최소 권한 원칙 (AI 컨텍스트에 제한된 정보만 제공)
- 응답 로깅 및 모니터링

## 3. UX Risks (사용자 경험 리스크)

### 3.1 시니어 사용성 문제

| 항목 | 내용 |
|------|------|
| **리스크 설명** | 시니어 사용자의 디지털 역량 부족으로 서비스 이용 불가 |
| **확률** | 높음 (4/5) — 타겟 사용자 특성 |
| **영향도** | 높음 (4/5) — 서비스 목표 달성 불가 |
| **위험도** | 🔴 16/25 (High) |

**완화 전략 (Mitigation):**
- 초대형 폰트 (최대 28px 기본)
- 대형 터치 타겟 (48px+ 최소, 권장 64px)
- 음성 안내 (TTS) 기본 활성화
- 음성 입력 (STT) 지원
- 온보딩 가이드 (단계별 튜토리얼)
- 최소 단계로 핵심 기능 접근
- "되돌아가기" 버튼 항상 표시
- 오류 메시지는 이해하기 쉬운 한국어

### 3.2 키오스크 호환성 문제

| 항목 | 내용 |
|------|------|
| **리스크 설명** | 다양한 키오스크 하드웨어/브라우저에서 렌더링 또는 터치 문제 |
| **확률** | 중간 (3/5) — 다양한 키오스크 환경 |
| **영향도** | 중간 (3/5) — 키오스크 채널 서비스 저하 |
| **위험도** | 🟡 9/25 (Medium) |

**완화 전략 (Mitigation):**
- 주요 키오스크 브라우저 사전 테스트 (Chrome Kiosk, Firefox Kiosk)
- 터치 이벤트 호환성 레이어 (pointer events 폴백)
- 300ms 터치 지연 제거 (touch-action: manipulation)
- 해상도별 레이아웃 최적화 (1920×1080, 3840×2160)
- 키오스크 모드 자동 감지 및 설정 적용
- 폴백: 키오스크 기기에서도 일반 모드 사용 가능

### 3.3 음성 인식 정확도

| 항목 | 내용 |
|------|------|
| **리스크 설명** | 시니어 음성(느린 말, 방언, 발음 불명확)에 대한 STT 인식률 저하 |
| **확률** | 높음 (4/5) — 시니어 음성 특성 |
| **영향도** | 낮음 (2/5) — 음성 입력 보조 기능이므로 |
| **위험도** | 🟢 8/25 (Medium-Low) |

**완화 전략 (Mitigation):**
- Web Speech API의 한국어 (ko-KR) 설정
- 실시간 중간 결과 표시 (interim results)
- 수동 수정 가능 (음성 인식 후 텍스트 편집)
- 음성 입력은 보조 수단으로 명시 (키보드 병행)
- 인식 실패 시 "다시 말해주세요" 안내 (TTS)

## 4. Operational Risks (운영 리스크)

### 4.1 서버 자원 부족

| 항목 | 내용 |
|------|------|
| **리스크 설명** | 동시 사용자 증가로 CPU/메모리 부족, 응답 지연 |
| **확률** | 낮음 (2/5) — 초기 단계, 사용자 수 제한 |
| **영향도** | 높음 (4/5) — 서비스 품질 저하 |
| **위험도** | 🟡 8/25 (Medium) |

**완화 전략 (Mitigation):**
- 응답 캐<0xC2><0xAD> 적극 활용 (TanStack Query staleTime)
- AI API 응답 캐시 (유사 질문)
- 정적 자원 CDN 활용
- 서버 리소스 모니터링 (CPU, 메모리, 응답 시간)
- 부하 테스트 수행 (목표: 동시 100명)

### 4.2 데이터 손실

| 항목 | 내용 |
|------|------|
| **리스크 설명** | SQLite 데이터베이스 손상, 디스크 장애 등으로 데이터 손실 |
| **확률** | 낮음 (1/5) — SQLite WAL 모드 안정성 |
| **영향도** | 매우 높음 (5/5) — 전체 데이터 손실 |
| **위험도** | 🟡 5/25 (Medium-Low) |

**완화 전략 (Mitigation):**
- SQLite WAL 모드 활성화 (동시성 + 안정성)
- 일일 자동 백업 (파일 복사)
- 백업 파일 외부 스토리지 이중화
- 콘텐츠 버전 관리 (수정 이력 보존)
- Prisma 트랜잭션으로 원자성 보장
- 정기 데이터 무결성 검사

### 4.3 외부 서비스 장애 전파

| 항목 | 내용 |
|------|------|
| **리스크 설명** | AI API, 이미지 서비스 등 외부 서비스 장애가 플랫폼으로 전파 |
| **확률** | 중간 (3/5) — 외부 의존성 존재 |
| **영향도** | 중간 (3/5) — 부분적 기능 장애 |
| **위험도** | 🟡 9/25 (Medium) |

**완화 전략 (Mitigation):**
- Circuit Breaker 패턴 적용 (5회 실패 시 30초 차단)
- 각 외부 서비스 독립적 타임아웃 설정
- 폴백 동작 정의 (AI → 고정 응답, 이미지 → 기본 이미지)
- 외부 서비스 상태 모니터링
- 장애 시 사용자에게 명확한 안내

## 4.4 PWA/서비스 워커 리스크

| 항목 | 내용 |
|------|------|
| **리스크 설명** | 서비스 워커 캐시가 갱신되지 않아 사용자가 오래된 콘텐츠를 보거나, SW 등록 실패로 오프라인 기능 미동작 |
| **확률** | 중간 (3/5) — SW 업데이트 메커니즘 복잡성 |
| **영향도** | 중간 (3/5) — 오프라인 기능 저하, 오래된 콘텐츠 |
| **위험도** | 🟡 9/25 (Medium) |

**완화 전략 (Mitigation):**
- SW 업데이트 감지 시 사용자에게 알림 표시
- Static 캐시는 버전 해시 기반 자동 갱신
- API 캐시는 5분 TTL로 자동 만료
- SW 등록 실패 시 온라인 전용 모드로 동작 (우아한 성능 저하)
- 캐시 버전 관리 및 강제 갱신 기능 제공

### 4.5 Hydration Mismatch 리스크

| 항목 | 내용 |
|------|------|
| **리스크 설명** | SSR/CSR hydration 불일치로 React 경고 발생, UI 깜박임 또는 기능 미동작 |
| **확률** | 낮음 (2/5) — useClientValue 훅으로 사전 방지 |
| **영향도** | 중간 (3/5) — UI 불안정, SEO 영향 |
| **위험도** | 🟢 6/25 (Low) |

**완화 전략 (Mitigation):**
- useSyncExternalStore 기반 useClientValue 훅 사용
- 모든 CSR 전용 값에 useClientValue 적용 (isOnline, isInstalled 등)
- Radix UI 컴포넌트 ID mismatch 방지
- reactStrictMode: false로 SW 이중 렌더링 방지
- E2E 테스트에서 hydration 경고 0건 확인

### 4.6 TWA/Android 호환성 리스크

| **위험도** | 🟢 4/25 (Low) |

**완화 전략 (Mitigation):**
- TWA 미지원 시 Chrome Custom Tab으로 자동 폴백
- assetlinks.json 공개 검증 도구 사용
- 다양한 Android 기기/버전에서 사전 테스트
- TWA는 부가 기능이므로 미동작 시 서비스 영향 없음
